# ai-tracker — 경기 영상 → 선수 위치 → 전술 보드

영상 속 선수를 AI로 탐지·추적하고, 팀을 구분한 뒤, 실제 피치 좌표(m)로 바꿔 전술 보드에 올릴 JSON을 만든다.
슛·패스 같은 이벤트 분류는 하지 않는다. **"누가 어디에 서 있었나"** 만 뽑는다.

```
영상 ──► calibrate.py ──► calib.json (영상 → 피치 변환)
    └──► track.py ──────► tracks.json + tracked.mp4 + minimap.mp4
                              └──► export_board.py ──► board.json (보드 앱 장면)
```

## 1. 설치 (처음 한 번)

```bash
cd ai-tracker
python -m venv .venv
# Windows: .venv\Scripts\activate   /  Mac: source .venv/bin/activate
pip install -r requirements.txt
```

- 첫 실행 때 YOLO 모델(`yolo11n.pt`, 약 5MB)을 자동으로 받는다.
- GPU가 없으면 CPU로 돈다. 1분짜리 영상에 수 분~수십 분 걸린다. 처음에는 10~20초 구간으로 테스트하자.

## 2. 캘리브레이션 — 가장 중요한 단계

```bash
python calibrate.py 경기.mp4 --time 12 --out calib.json
```

창이 두 개 뜬다.

1. `frame` 창에서 경기장 위 기준점(코너, 페널티박스 모서리, 하프라인 끝, PK 스팟 등)을 클릭한다.
2. `pitch` 창에서 **같은 지점의 회색 점**을 클릭한다. 가까운 점에 자동으로 붙는다.
3. 4쌍 이상 찍으면 영상 위에 분홍색 라인이 겹쳐 그려진다. **실제 흰 라인과 겹치면 성공이다.**
4. `s` 또는 Enter를 누르면 저장된다. `u`는 마지막 쌍 취소, `q`는 저장 없이 종료다.

함께 저장되는 `calib_preview.jpg`로 결과를 다시 확인할 수 있다.

**실수하기 쉬운 부분**

- **한 줄 위의 점만 찍으면 실패한다.** 예를 들어 골라인 위 4점만 찍으면 안 된다. 앞뒤·좌우로 퍼진 점을 5~6개 찍어야 한다.
- 화면 상단 `err` 값은 1m 이하가 목표다. 2m를 넘으면 잘못 찍은 쌍이 있다는 뜻이니 `u`로 지우고 다시 찍는다.
- 아마추어 구장은 105×68이 아닌 경우가 많다. 실제 크기를 알면 `--length 100 --width 64`처럼 넣는다. 크기가 틀려도 상대적인 형태(라인 간격, 대형)는 유지된다.

## 3. 추적

```bash
# 고정 카메라 (캠코더 + 삼각대)
python track.py 경기.mp4 --calib calib.json --start 12 --end 42 --out-dir out

# 지금처럼 손으로 찍거나 카메라가 좌우로 도는 영상
python track.py 경기.mp4 --calib calib.json --end 42 --out-dir out --camera-motion
```

결과물:

- `out/tracked.mp4`: 원본 영상에 박스, 팀+ID(A3, B7…), 우하단 미니맵이 표시된다. **먼저 이걸 눈으로 확인한다.**
- `out/minimap.mp4`: 2D 보드 화면만 담긴 영상이다.
- `out/tracks.json`: 프레임별 좌표 원본이다.

자주 바꾸는 옵션:

| 옵션 | 언제 |
|---|---|
| `--device 0` | NVIDIA GPU가 있을 때 (`mps`는 맥) |
| `--model yolo11s.pt` | 멀리 있는 선수를 놓칠 때 (더 정확하지만 느림) |
| `--imgsz 1920` | 선수가 화면에서 아주 작을 때 |
| `--stride 2` | 속도가 너무 느릴 때 (2프레임마다 처리) |
| `--margin 2` | 피치 밖 몇 m까지 사람으로 칠지. 벤치·관중이 잡히면 0으로 |

## 4. 보드용 장면 추출

```bash
python export_board.py out/tracks.json --every 2 --out board.json          # 2초마다
python export_board.py out/tracks.json --times 15,18.5,22 --out board.json # 원하는 순간만
```

| 옵션 | 용도 |
|---|---|
| `--swap-teams` | A/B가 원하는 팀과 반대로 나왔을 때 |
| `--rotate` | 공격 방향을 보드의 왼→오로 맞출 때 (180도 회전) |
| `--include-other` | 심판·GK(다른 색 유니폼)도 포함할 때 |

`board.json` 구조:

```json
{
  "meta": {"pitch": {"length": 105, "width": 68}},
  "teams": {"A": {"color_bgr": [..]}, "B": {...}},
  "scenes": [
    {"time": 15.0, "label": "00:15.0",
     "players": [{"slot": "A1", "team": "A", "x": 32.4, "y": 20.1, "nx": 0.309, "ny": 0.296}],
     "ball": null}
  ]
}
```

- `x, y`는 m 단위이고 원점은 왼쪽 위 코너다. `nx, ny`는 0~1로 정규화한 값이다. 보드 앱 좌표계에 맞는 쪽을 쓰면 된다.
- `slot`(A1, A2…)은 장면 사이에서 가장 가까운 선수끼리 이어 붙인 번호다. 트래커 ID가 중간에 바뀌어도 보드 애니메이션이 튀지 않는다. **등번호는 아니다.** 보드에서 직접 이름을 붙이면 된다.

## 알려진 한계 (정직하게)

- **ID 바뀜**: 선수끼리 겹치면 추적 ID가 바뀐다. 장면 단위 보드에서는 `slot` 매칭으로 대부분 해결되지만, 연속 궤적 분석(뛴 거리 등)에는 아직 쓰면 안 된다.
- **팀 구분**: 유니폼 색만으로 나눈다. 두 팀 색이 비슷하거나 조끼를 입으면 틀린다. 심판·GK는 대부분 `other`로 빠진다.
- **공**: 기본 모델(COCO)은 공을 자주 놓친다. 공이 떠 있으면 위치도 틀어진다. 보드에서는 손으로 놓는 게 현실적이다.
- **카메라 움직임 보정(`--camera-motion`)**: 실험 기능이다. 배경 특징점으로 카메라 이동을 따라가는데, 오래 돌리면 오차가 쌓인다. 줌을 크게 바꾸거나 화면에 잔디만 보이는 구간에서는 틀어진다. **30초 안팎 구간 + 그 구간 첫 프레임에서 캘리브레이션**이 안전하다.
- **화면 밖 선수**: 카메라에 안 잡힌 선수는 당연히 안 나온다. 대형 전체를 보려면 결국 고정 캠코더로 전체 피치(최소 하프 이상)를 담아야 한다.

## 캠코더 살 때 체크

- 삼각대 고정 + **높은 위치**(관중석 꼭대기 등)에서 찍어야 선수끼리 덜 겹친다. 높이가 정확도에 가장 큰 영향을 준다.
- 줌은 고정하고 하프라인 근처에서 피치 전체를 담는다.
- 1080p 30fps면 충분하다. 4K는 처리만 느려진다.
